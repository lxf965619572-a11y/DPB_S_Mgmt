| 子类 | 数量 | 定义 |
|---|---|---|
| **(a) 纯桩** | **15 个** | 函数体内**零个** `return ERROR_*`，只有 LOG / 置标志 / `return SUCCESS` |

## 总体定性结论

> **这是系统性工程实践问题，不是个别疏忽。** 四条独立证据链，每条都指向同一结论：

### 1. 比例证据

- **18.7%** 的 int 返回型函数（36/193）在下游失败时仍返回 SUCCESS
- `tcp_client_send` 的错误传播率是 **0/19 = 0%**
- `add_ie` 忽略率 **75%**
- `pthread_mutex_lock` 忽略率 **100%**

**个别疏忽不会呈现这种量级和均匀度。**

### 2. 模板证据

- **10 个模块 init 是逐字同构的复制粘贴桩**（普查 1 #1-#10），`main.c:228-321` 为它们写了 **10 段恒假的错误处理**
- **12 处 `return (len > 0) ? SUCCESS : ERROR_GENERAL`** 结构完全一致
- **6 个 `g_xxx_initialized` 标志 + init/cleanup 对**是同一份代码

→ **假成功是被复制传播的，不是被独立犯下的。**

### 3. 双标证据（最关键）

同一个项目里：

| 做对的 | 数据 |
|---|---|
| `cpri_encode_message` | **19/19 检查** |
| `fpga_encode_message` | **12/12 检查** |

### 4. 后果证据

假实现**直接掩盖**了单位换算链的所有缺陷（见 [09-协议一致性](09-协议一致性.md)）：
- 校准查询硬编码成功 → 校准失败无人知
- 环回结果 = write 返回值 → 环回测试不可信
- 复位动作被注释 → 复位无效但报成功
- 通道建立 result 恒 0 → 建链失败但报成功

**每一处假成功都在阻止下一层问题被发现。**
