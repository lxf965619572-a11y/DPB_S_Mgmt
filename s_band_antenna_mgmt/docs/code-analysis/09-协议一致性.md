## 1. CPRI 消息头 15 字节布局：四源一致，且有字节级实证

### 1.1 代码定义

见 [07 §2.1](07-架构与数据流.md#21-北向-cpri-消息头15-字节packed)。`include/cpri_protocol.h:48-55`，编码 `src/cpri_protocol.c:115-152`。

### 1.2 关于「未对齐 uint32 陷阱」的核查结论

**当前实现规避了，但有一处残留隐患。**

头结构是 `4+4+1+1+1+4 = 15` 字节 packed，所以 `serial_num` 位于**偏移 11**——一个 4 字节字段落在奇数偏移上。当前代码用 `memcpy` 读写（`cpri_protocol.c:129-141`），规避了直接解引用。

⚠️ **残留隐患**：`param_config.c:198`/`:207`/`:216` 三处把 payload 偏移处**直接强转为含 uint16/uint32 成员的结构体指针**，offset 由前一个 IE 的 `ie_length` 累加而来，可以是任意值 → **非对齐访问 UB**（ARMv8 容忍，但依赖 packed 属性）。

### 1.3 字节序：裸小端，三源一致

`main.c:118-120` 直接 memcpy 偏移 4 读长度做粘包切分，注释明说「**D2000 CPU是小端序，直接读取**」，不做任何字节序转换。

### 1.4 `msg_length` 是否含头部：**含**，四源一致，有精确实证

`msg_length = 15 + payload_len`。

实证：`payload_len=291` 与「IE2 总长 9」精确吻合（见 §2.4）；`60 = 15+45`（msg 31）；`626`/`304` 字节精确闭合（msg 2/21）。

### 1.5 `cpri_decode_message` 的长度校验确实形同虚设

`:178` 发现 `msg_length` 与实收长度不符时**只打日志不拒绝**。配合 `main.c:123` 只校验 15~8192 范围 → 见 [03 §A8](03-P0-阻断级问题.md#a8-入站-payload-长度零校验)。

## 3. 南向 FPGA UART 协议（`/dev/ttyAMA0`）：两种帧格式，length 语义在两版之间变过

### 3.1 命令帧 vs 遥测帧是**两种不同布局**

不是「同一字段的三种理解」：

| | 命令帧（下行） | 遥测帧（上行） |
|---|---|---|
| 帧头 | `0xEB90`(2, 大端) | `0xEB90`(2) |
| msg_id | 有(1) | **没有**（`fpga_protocol.h:141-144` 特别注明） |
| length | 1 字节 | **2 字节**（大端，值=127） |
| 数据 | N | 127 |
| 帧尾 | `0x5555`(2, 大端) | `0x5555`(2) |
| 总长 | 可变 | **固定 133 字节** |

### 3.2 length 字段语义**在版本间被改过**，日志实证

| 版本 | 发的 length | 语义 |
|---|---|---|
| 旧构建 | `length=2` | N+2 |
| 当前 | `length=1` | N |

**FPGA 两版都接受** → **无法判定哪个符合规范**。

三处定义互不一致：`:98` 注释（N+2）、`:99` 代码（N）、`:167` 解码（N+2，死代码）。→ **`encode(decode(x)) != x`**。

## 13. 单位换算链审计结论（Gap 专题 7）

审计范围：`fpga_protocol.c`、`fpga_handler.c`、`cell_config.c`、`channel_setup.c`、`status_query.c`、`param_query.c`、`fpga_to_cpri.c`、`uart_client.c`、`loopback.c`、`alarm_manager.c`、`main.c`、`msg_handler.c`、`param_config.c`、`cpri_protocol.c` 及全部 `include/*.h`，逐行读完；日志侧对 `logs/` 全量统计。

### 链 A：下行/上行中心频率

| 结论 | 说明 |
|---|---|
| **A-1 单位自洽性** | ✅ **代码层面自洽，且有实测数据独立佐证** |
| **A-2 关于「500 kHz 量化」** | ⚠️ **这个前提是错的，编码是 1 kHz 无损的** |
| **A-3 但 `× 2` 是一个未文档化的魔数** | ❌ **构成真正的风险（严重度高）** → 见 §12 P0-1 |
| **A-4 quotient 存 uint8_t** | ⚠️ 无范围检查，静默回绕（严重度中，**S 频段本身不触发**） |
| **A-5 payload 排布 `DL(4) + BW(4) + UL(4)`** | ⚠️ **函数签名顺序与线上顺序不一致**（严重度中） |
| **A-6 本振频率回路** | ❌ **完全不可观测**（严重度高，**直接阻断了单位链的现场闭环**） |

### 链 B：带宽（本次调查的核心，**结论最严重**）

**B-1 代码事实**：频率做了压缩编码（`fpga_protocol.c:64-65`），**带宽原样透传**（`cell_config.c:495-497` → `fpga_send_freq_band(dl, ul, bw)`）。这个**不对称**是有意还是遗漏，无从判定。

**B-2/B-3 日志实测值裁定 —— 决定性证据：不存在任何能让数据自洽的单位**

**关键事实 1**：两个小区在**同一时期、同一 S 频段内**，用**相差 1000 倍**的 bw 值同时配置。

`log.1`（2026-07-21 → 2026-08-11）单个文件内同时存在：

| cell_id | dl_freq (kHz) | ul_freq (kHz) | bw | 出现次数 |
|---|---|---|---|---|
| 3 | 2140100 | 1950100 | **20000** | 492 |
| 2 | 2180100 / 2180000 / 2158200 / 2155260 | — | **100** | 391 |

**B-4**：「频率压缩、带宽透传」的不对称——是有意还是遗漏？**无法判定**。

**B-5 FPGA 是否拒绝过错误带宽？—— 没有拒绝机制，物理上不可能拒绝（严重度：致命）**

四重证据：

1. **协议层无 ACK/NACK**。`src/uart_client.c:227-251`：只有一种帧被解析——`if (expected_frame_len == 133 && length_field == 127)` 走 `fpga_decode_status_frame`；**其他所有帧**走 `client->on_data_received(buf_start, expected_frame_len)`（`:249-250`）
2. **那个回调是空壳**。`src/main.c:167-172`：
   ```c
   static void on_uart_data_received(const uint8_t *data, uint32_t len)
   {
       (void)data;  /* ... */
   ```
3. 遥测帧**无校验和**（§3.3）
4. `fpga_send_freq_band` 的返回值在 `cell_config.c:495-498` 被检查，但那只是 **UART write 的返回值**，不是 FPGA 的应答

→ **错误的带宽会被 FPGA 照单全收（或静默忽略），PAAU 永远不知道。**

### 链 C：功率

| 结论 | 说明 |
|---|---|
| **C-1** | 全部实测值与四种单位解释的算式已列出 |
| **C-2 物理合理性** | ❌ **按 1/256 dBm 解释，遥测的两个功率值物理上不可能** |
| **C-3 `cell_power` 到底有没有作用** | ✅ **按 1/256 dBm 解释是合理的，而且有强统计证据** |
| **C-4 有没有任何地方做 1/256 dBm ↔ dBm 换算** | ❌ **所有上线路径都是原始 1/256 单位值裸传** |

### 链 D：Toffset / T2a / Ta3

| 结论 | 说明 |
|---|---|
| **D-1 单位** | ❌ **代码里完全没有任何说明，无法判定** |
| **D-2** | 实测值与候选单位的算式（1 chip = 1/3.84 MHz = **260.4167 ns**） |
| **D-3** | ⚠️ **实测到一处无法解释的异常：T2a 与 Ta3 的值成对互换** |
| **D-4 降级填 0 与真实 0 无法区分** | ✅ **已确证，且有精确计数证据** |

### ⑧ 三条链的最终裁定（一句话版）

- **链 A（频率）**：代码自洽，但 `×2` 魔数待 FPGA 方确认，本振回路不可观测
- **链 B（带宽）**：**致命**——单位无法自洽 + FPGA 无拒绝机制 + 假成功掩盖
- **链 C（功率）**：上行遥测物理上不可能，下行 `cell_power` 合理但无换算
- **链 D（时延）**：单位完全未知，且实测到值互换异常

| 类别 | 说明 |

| **C. 死代码** | 零调用者，已 grep 全项目含 `tests/` 确认 |
